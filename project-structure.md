# Project Structure

One-line description of every file in this project, extracted from `AGENTS.md` — keep it up to date per the Core Principles.

- `AGENTS.md` — agent guidelines for this repo: the core principles plus links to `project-structure.md` (this file) and `project-maintenance.md`.
- `README.md` — repo front page for first-visit GitHub users: one-line project description, live-site link, quick-start commands, and a short how-it-works overview deferring to `AGENTS.md` and `data/` for depth.
- `project-structure.md` — this file: the one-line description of every file in the project, extracted from `AGENTS.md` and kept up to date per the Core Principles.
- `project-maintenance.md` — project maintenance reference extracted from `AGENTS.md`: the game-repo subject-matter expert notes (baseline, repo access, citation legend, data-file→game-code map, drift hotspots, maintenance workflow, hard rules) and the agent's GitHub access notes.
- `package.json` — zero-dependency manifest defining the `build`, `test`, `extract:quests`, `extract:pokedex`, `extract:sprites`, `screenshots`, and `verify:citations` npm scripts.
- `.gitignore` — ignores the vendored `references/` game source, the generated `dist/` build output, and the captured `test/ui/screenshots/` PNGs.
- `.github/workflows/pages.yml` — GitHub Actions workflow that runs the test suite on pushes to `main`, pull requests targeting `main` and manual dispatch (plus a separate `ui` job that installs Playwright and re-runs the suite for real browser coverage, since the `test` job's UI tests self-skip, and a `verify` job that shallow-clones the upstream game repo at the two baseline SHAs from `scripts/verify/baseline.json` and gates merges on `npm run verify:citations` — issue #55), and (for non-PR events) builds and deploys `dist/` to GitHub Pages (major-tag action pins, with a note that SHA-pinning is the stronger option for deploy workflows).
- `data/adventure.json` — adventure-path reference data: how each run's path is generated, all 16 room types with their placement rules and weights, the 14-boss ladder (8 gyms, 4 Elite Four, Champion, final) and the victory lap.
- `data/campaigns.json` — legacy-campaigns reference data: the seven hidden-phrase campaign modes (BST Cup, Classic, Battle Addict, Auto Battler, LaterManner, Limited Capture, One Hit), their unlock phrases, per-mode rules and the low-is-better scoring system.
- `data/charms.json` — charms-and-curses reference data: all 17 Charms and 26 Curses with per-item effects, stacking/cap formulas and item sources, plus the one Vanilla-vs-EX mechanical divergence (the Grace cap: 90 vs 150) and the Vanilla 'DISCOUND CURSE' typo.
- `data/followmons.json` — overworld-followmon reference data: the six spawn slots, spawn timers and tile-placement rules, water and Safari Zone spawning, shiny sparkles, shiny odds, the lead-Pokémon follower, encounter chains and the catch flow, all identical between the versions.
- `data/game-modes.json` — game-modes reference data: Classic, Gauntlet and Fast Path rule sets with per-branch source citations (identical in Vanilla/EX).
- `data/gameshow.json` — game-show reference data: Randoman's skill/luck games (with Team Trivia currently disabled in code), the escalating-option rounds, the all-or-nothing prize shelf, and the cheater's Electrode, with the only vanilla-vs-EX difference being shelf sprite repositioning.
- `data/hub.json` — hub reference data: the 11 buildable hub areas and all 48 workbench upgrades with costs, requirements and player-facing effects, plus wander mons, time/season behaviour and home decor, noting the three Vanilla-vs-EX upgrade divergences.
- `data/pokedex.json` — Pokédex reference data (lazy-loaded, `meta.lazy`): one record per numbered species in the Expansion national dex (#1–#1025: 1025 records, 386 shared, 639 EX-only, the 25 Vanilla-only legacy Unown letters excluded) with stats, types, abilities, catch rate, height/weight, gender, egg groups, base EXP, Pokédex text, evolutions as the in-game Pokédex displays them (issue #97 — the raw table run through the shared `Rogue_ModifyEvolution` port in `scripts/extract/evolutions.mjs`: `evo.evos` = the surviving branches as `{id, method, form?}`, `evo.prev` = the lowest-dex-number record whose `evos` target this species (the claiming source may itself be a dex-less form — Galarian Yamask → Runerigus — in which case `prev.form` names it); `form` names the branch target's / prev source's form — exactly the base record's own `forms` entry — whenever that species value is not the record's own (Quilava's Hisuian Typhlosion; never in the Vanilla build); forms carry their own `evo` where they have branches — the rewrite is keyed by the species value held), profile-derived learnsets (level-up/TM/tutor), structured forms (per-form name, types, stats, abilities, height/weight, description where the entry has one, `evo` where the form has branches, and `form.sprite` — the form's own `<formEntryId>.png` — where it owns its art), dex-variant membership, ride moves, legendary-encounter notes and a `vanilla` overlay of only the differing fields, plus a top-level `catalog` (issue #99) — the move & ability reference behind the detail tables: `moves` keyed by display name (the EX `{type, power, accuracy, pp, effect?}` values, 0/none → null, placeholder descriptions → null; Dynamax Max Moves beyond `MOVES_COUNT` get no entry) and `abilities` (the EX descriptions, a colliding name's entries joined with ` / `), `catalog.vanilla` the diff-only Vanilla overlay (moves/abilities sub-keys omitted when empty), the top-level `typeChart` (issue #100) — the per-build damage-multiplier table: the EX 20-type 20×20 matrix (the `#if B_STEEL_RESISTANCES >= GEN_6` guard resolved through the build config — Ghost/Dark do not resist Steel in the shipped build) with the diff-only `typeChart.vanilla` overlay (the 18-type pre-Gen-6 table, differing on exactly the two Steel-resistance cells) — and the five short prose blocks (the-dex/reading-entries/moves/sprites/viability) each carrying its 1–2 sentence rule + dense facts in a `list` fact array rendered as a scannable fact list (issue #84; the viability block documents the analytics metrics as formulas — the numbers are computed from the site data at run time).
- `data/quests.json` — quest reference data: every quest across the nine display groups with plain-language triggers, requirements, rewards and flags, plus per-quest version availability (138 shared, 94 EX-only) and source citations.
- `data/routes.json` — routes reference data: all 36 routes (12 Hoenn, 6 Kanto, 6 Johto, 12 Sinnoh) with region, terrain, three-type wild tables and drop rarity, the calm/average/tough sub-type rules, and per-route `differences` for the six EX FAIRY typing swaps.
- `data/safari.json` — Safari Zone reference data: the 60-slot pool layout (0–44 regular, 45–59 legendary), the four entry criteria, the run-start illegal ribbon that gates every pool push (incl. the Starter Bag starter-loss edge case), the priority/eviction rules, and the Legends Cave offering flow (identical between the versions apart from the legendary roster per build).
- `data/settings.json` — run-configuration reference data: every difficulty toggle, range and preset with its forced-toggle matrix, noting Vanilla-vs-EX divergences.
- `data/site.json` — central site config (nav order, page titles/descriptions, the live-site base URL `site.url` — the single source for the emitted sitemap/robots and the shells' `og:url` — version labels, hero, footer, the pokedex `dex.pageSize` tile page (24 — the site's page; the in-game Overview draws 28), search-palette config incl. the `maxResults` cap and the `moreResults` overflow copy) bundled by the build and consumed by every page.
- `data/timeofday.json` — time-of-day-and-seasons reference data: the six-keyframe palette tints, Dawn/Day/Dusk/Night time codes, the run/hub clocks, bed time presets, the two-day seasons with seasonal hub music, and the EX-only seasonal and time-of-day species gating.
- `data/unique-mons.json` — unique-Pokémon reference data: the five-slot Unique Lab, the 1/7–2/7 rarity roll with lab-upgrade downgrades, bonus move/ability pools (larger in EX), the Unique Typings format, the detection alert, the 50% wild conversion and the catch rules, plus the 37 static custom mons.
- `data/versions.json` — vanilla-vs-EX reference data: the EXPANSION build flag, the Gen 1–9 roster/Pokédex, Gen 4–9 mechanics, extended trainer regions, boss aces and balls, the six Fairy route swaps, HM removal, affection, item naming, and the master list of every version divergence with the verified byte-identical core.
- `scripts/build.mjs` — zero-dep Node build that copies `site/` to a temp dir (`dist.tmp-<pid>`, excluding the repo-internal `css/DESIGN.md`) then publishes it in place (every temp file is atomically renamed onto its `dist/` path — a per-file atomic replace, so readers never observe a missing or half-written file even when suites build concurrently under `node --test`; stale entries are removed after the renames), validates the `data/*.json` envelope (incl. `meta.id` matching `/^[a-z][a-z0-9-]*$/` so the derived `ROGUE_DATA_*` bundle globals can't be injected, and the reserved-stem check — a `meta.lazy` file whose stem is `bundle` fails naming the file, since its chunk would clobber the shared `dist/data/bundle.js`) plus the four UI prose contracts the pages regex-parse at run time (quest display groups, the safari slot-layout ranges, the routes "Wild types:" differences, the ≥5 campaign phrases) plus the site.json SEO config (`site.url` absolute + every nav entry's title/description), and emits `dist/data/bundle.js` (the 14 non-lazy data files) plus one lazy `dist/data/<stem>.js` chunk per `meta.lazy` file (currently only `pokedex` — loaded by `pokedex.html` alone, never into the shared bundle), `dist/sitemap.xml` (the ten nav pages as absolute URLs with build-time `<lastmod>`; 404.html excluded) and `dist/robots.txt` (allow-all + sitemap reference) — all written into the temp dir before the rename (never reads `references/`).
- `scripts/extract/evolutions.mjs` — the shared zero-dep evolution machinery (issue #97, imported by BOTH extractors and the sprite-forms drift test — the single source of the evo rule): the line-faithful `Rogue_ModifyEvolution` port (`modifyEvolution`/`buildEvoDisplayList` — the raw EX `species_info` tables incl. the Meltan `GetBaseEvolution` override, and vanilla `evolution.h`, become the post-rewrite branch lists the in-game Pokédex displays: per-branch resolved EVO_* constants, the item/nature display names from `items.h`/`rogue_items.h`/`nature_names.h` — pass-through byte-identical to the in-game strings except the documented 2-entry `exItemNameCorrections` for the mangled EX names (items.h L10066/L10076) — and the ModifyKnowMoveEvo level-up profile check — u16-faithful: the species' level-up profile (the `expansion_profile.json` / vanilla learnsets' C move symbols, resolved to values via the branch's `moves.h` with `parseMoveValues`) is compared against evo param: profile knows the move → level evo at max(38, the profile's level) for plain AND two/three-segment know-move evos; a profile that LACKS it → level 30, and only for plain `EVO_MOVE` (two/three-segment methods stay raw) — and the survivor cap (the in-game display list is scrollable, so all survivors ship; the port hard-fails beyond 8)), the shared `evoLinks` pass (per-branch/prev `evoFormOf`/`prevOf`/`refs`: value-identity form naming, the [dexNum, isForm] prev fixpoint, the alias-base guard — a prev source is a form only when its value differs from its record's own — and the roster additions the in-game display implies), and `exEvoRosters` (re-runs the port over the nine gen_1..9 species tables — the pokedex entry domain — and reports the form ids the post-rewrite lists reference, the identical refs both extractors apply); also `parseItemValues`/`parseMoveValues`/`evoTuplesOfBody`/`makeEvoConsts` and the per-branch build seeds + constant-header lists.
- `scripts/extract/pokedex.mjs` — dev-only zero-dep Pokédex extractor (`npm run extract:pokedex`, `--repo`/`--out`/`--check`): the shared `preprocessor.mjs` (real build config, `P_`/`B_` toggles) parses the Expansion species tables (1505 initializers — the 60 form groups without an initializer of their own get a synthesized base record, the 540 dex-less forms are not records) and Vanilla's `base_stats.h`/`pokedex_entries.h`/`pokedex_text.h`, joined by national dex number, plus per-species learnset profiles, dex-variant membership (`RoguePokedex_IsSpeciesAllowed`), TM learnability (`CanSpeciesLearnTM`), rides and legendary encounters, the top-level `typeChart` (issue #100 — the EX `sTypeEffectivenessTable[20][20]` uq4_12 matrix sliced from `src/battle_util.c` with its one `#if` guard resolved through the build config, and the Vanilla `gTypeEffectiveness[336]` triple list sliced from `src/battle_main.c` — unlisted pairs neutral, the TYPE_FORESIGHT/TYPE_ENDTABLE pseudo-type sentinel rows excluded — the diff-only vanilla overlay emitted only when the shared cells genuinely differ), the top-level `catalog` (issue #99 — per-branch move stats from `battle_moves.h` + in-game descriptions from `move_descriptions.h` (multi-line `_()` concat, the `gMoveDescriptionPointers` value table, ternary powers via the shared preprocessor, the `BINDING_TURNS` string macro spliced in by a raw-directive walk that ignores the file's trailing `#undef`), ability descriptions from `abilities.h` (same-name EX entries joined), EX values keyed by display name + the diff-only `catalog.vanilla` overlay), evolutions run through the shared `Rogue_ModifyEvolution` port in `evolutions.mjs` (`src/rogue_baked.c` — issue #97; the form-targeted branches and form-sourced prevs gain their `form` display names, and the referenced forms join the documented rosters via the shared `evoLinks` pass so every form the in-game Pokédex can show ships its sprite), and each record's forms as structured per-form objects (resolved from the form's own EX species_info entry — `form.sprite = <formEntryId>` on every roster-referenced own form per the shared `sprite-forms.mjs` rule, each such form's resolved EX sprite source — front file, plus the palette when it lives outside the form's front dir — folded into the record's `source` citation, name-only for the custom forms without art), and `buildDoc` emits the five short prose blocks with `list` fact arrays (the two count-templated blocks keep their interpolations; the #100 viability block documents the analytics-metric formulas) — regenerates `data/pokedex.json`, reading vanilla from the working tree and expansion via `git show origin/expansion`.
- `scripts/extract/preprocessor.mjs` — the shared zero-dep miniature C preprocessor (imported by pokedex.mjs and the `evolutions.mjs` module sprites.mjs runs through — moved verbatim from the pre-extract inlines): the `Preprocessor` class (per-branch file providers over the working tree / `git show origin/expansion`, `#include` resolution, `#if`/`#ifdef` gating with the Makefile release-build defines from `seedDefines`, enum collection via `collectEnums`, constant/expression evaluation via `resolveConst`/`evalExpr`).
- `scripts/extract/quests.mjs` — dev-only zero-dep quest extractor that replicates the game's CustomJson quest loader (includes, file defaults, `#if` version gates, template expansion, `UNLOCKED_BY_DEFAULT`) and regenerates `data/quests.json`, reading vanilla from the working tree and expansion via `git show origin/expansion`.
- `scripts/extract/sprite-forms.mjs` — shared zero-dep form-sprite module imported by BOTH extractors (the single source of the form→art rule): the flat `site/assets/pokemon/<formEntryId>.png` naming convention (`formSpriteFile`), the INCBIN front/palette table parse of the EX `src/data/graphics/pokemon.h` plus `##`-concatenation/macro expansion of the raw EX species tables, `formSpriteManifest` (per-entry own / base-identical / the pinned `silvally_fairy` ternary / no-entry classification — a no-entry custom form deliberately gets no file and the site falls back to the base sprite), and `formRosterDomain` (rule 5: an `own` form ships a file only when some record's form roster references it — unreferenced species-table data gets no file; the domain also carries `dexValue` for the evo pass) plus `addExtraRosters` (the pure merge of the evo-referenced additions onto a base domain).
- `scripts/extract/sprites.mjs` — dev-only zero-dep species-sprite extractor (`npm run extract:sprites`, the generator behind the DESIGN.md §10 exception): for every species dir in the union of both branches' `graphics/pokemon/`, decodes the indexed 4/8-bit front art (vanilla working tree: `front.png` — six 64×256 stills take frame 0, plus the castform/unown fallback layouts; expansion via one `git cat-file --batch`: `front.png` or the first 64×64 frame of `anim_front.png`), composites it with the species' JASC `normal.pal` (index 0 always transparent; 8→5→8-bit round-trip so output matches the GBA LCD), and writes a byte-deterministic 128×128 RGBA PNG per species to `site/assets/pokemon/` — `<id>.png` vanilla-preferred, and the branch-divergence guard byte-compares every shared id, emitting `<id>-ex.png` + printing the full divergent list — plus the manifest-driven per-form pass (every non-base EX species entry classified by the shared `sprite-forms.mjs`: roster-referenced `own` forms — plus the forms the shared `exEvoRosters` evo pass references (over the gen_1..9 tables only, the pokedex entry domain) — ship a flat `<formEntryId>.png` composited through the same pipeline, unreferenced-own / base-identical / the pinned ternary / no-entry forms get no file, a full per-form resolution report is printed); `--check` covers the form outputs too, verifying the committed outputs are up to date (missing/stale/unexpected → exit 1).
- `scripts/verify/baseline.json` — machine-readable baseline of the game revision the site documents (Vanilla/expansion SHAs + in-game versions), read by verify:citations --changed — the only place those SHAs are recorded.
