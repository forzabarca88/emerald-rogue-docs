# AGENTS.md

## Core Principles

- **DESIGN AND BUILD PRODUCTION GRADE CODE FROM THE START** - i.e. no monolithic files when they can modularised, no unnecessary duplication of code, no hardcoded values when they can be placed in a centralised config file, etc.
- Keep AGENTS.md minimal - **only** keep information which will be required every time you look at this project. Project structure should **always** be kept up to date, and include a CONCISE single sentence description of each file in the project.  Do not modify `Core Principles`, but review and remove anything else from the document which is not required.
- Never write to `main` branch directly when interacting with the Github repository. The workflow must always be `push non-default-branch` -> `create pull request into main branch` -> `ensure successful actions workflow completion (if applicable)` ->  `merge pull request into main branch` -> `delete the merged branch`.
- Do **not** make assumptions without testing and validating first. Follow the scientific method.
- You **must** review your own code as you write as a *Senior Software Engineer*.
- Write the bare minimum of tests - follow **ARRANGE, ACT, ASSERT**. You must test the end result, NOT the implmentation details.
- When fixing bugs or issues, you must replicate the problem with a failing test first. The failing test should go green once you fix the application code.
- If you start the application (e.g. for testing), you must validate that the application is stopped before marking the task complete.
- Use mocks for testing sparingly - if the code requires excessive mocking, then redesign the implementation to be easier to test.
- **You must assume that your knowledge is outdated** - always research topics and frameworks before making decisions.

### Project Maintenance - Github Notes

GitHub access from the agent is a GitHub App installation (`my-pi-agent-app[bot]`) provided by the `pi-github-app-auth` Pi extension. The correct way to interact:

- **Git**: plain `git fetch/push/pull` just works — the extension injects `GH_TOKEN` (installation token) and an ephemeral `credential.https://github.com` helper into agent bash. **Never** add manual auth (tokens in URLs, `-c http.extraHeader=…`): it conflicts with the helper and fails with "invalid credentials". GitHub SSH is deliberately blocked in agent shells.
- **API**: `curl -H "Authorization: Bearer $GH_TOKEN" https://api.github.com/repos/forzabarca88/emerald-rogue-docs/…` (the token is in the agent env; never print it).
- **App-token quirks** (verified): `GET /user` 403 and the repo `permissions` map all-false are normal, not permission problems. `POST /repos/…/branches` 404s — create/delete branches via `POST /repos/…/git/refs` / `DELETE /repos/…/git/refs/heads/<branch>` instead. Contents API: `PUT` takes `branch` (branch must already exist), `GET` takes `ref`. There is no API to delete PRs or issues — close them (the web UI can delete draft PRs).
- **Workflow** (per Core Principles): `git push origin <branch>` → `POST /pulls` (base `main`) → poll `GET /actions/runs?head_sha=<head-sha>&event=pull_request` until `status=completed` and require `conclusion=success` (per-job detail: `/actions/runs/{id}/jobs`) → `PUT /pulls/{n}/merge` (merge commit, matches repo history) → `DELETE /git/refs/heads/<branch>` → `git fetch origin main:main` to fast-forward local `main`. Always compare branch state against `origin/main`, not a possibly-stale local `main`.
